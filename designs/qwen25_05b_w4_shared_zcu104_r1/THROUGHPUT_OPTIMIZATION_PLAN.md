# 200MHz throughput optimization candidates

Historical initial plan (before supply and N8 implementation). Current implementation/evidence is in EXECUTOR_THROUGHPUT.md and STATUS.md.

2026-10-07. Planning analysis only: no RTL/ISA/numeric change, no new throughput PASS. Corrected board007/host SD003 remains the runnable baseline. Existing module cycles and exact source evidence are in EXECUTOR_THROUGHPUT.md and evidence/executor_throughput_run001/report.json.

The largest dense-decode cost is the GEMM controller serializing bank reads, dot completion and dependent accumulator completion. The64 products are spatially parallel; the FP32 pipelines accept streaming work but the dot busy flag and executor FSM currently allow only one dot transaction. Full W4 step costs62 cycles, and N128/K128/M1 ACCUM costs16640cycles. Current dense compute estimate is2.507s/token, excluding attention, nonlinears, transfer and control.

Preserve:200MHz; K16/output4/row1 physical arithmetic width; current ISA and command chunk semantics; exact adjacent tree16 and sequential K16/group accumulation order per output; RNE/FTZ/BF16 boundaries; finite/error rules; PS/PL tensor boundary. Independent outputs may be interleaved without reassociating any output's additions. New scratch capacities/resource use and timing require measured synthesis and route; current timing margin+0.009ns is small and routing was congested.

Candidate1: improve bank service and operand reuse. Cache each ACT group128 (256bytes BF16), cache/reuse both K16 halves of each packed W4 word, issue fixed-latency reads in consecutive cycles with delayed address/role tags. Keep dot and accumulator sequencing initially. Architectural arithmetic wait alone is(31+7)*256=9728cycles per tile, so a bank-only change cannot achieve a10x improvement. Approximately1.3–1.6x W4 module speed is an analysis target, not measured evidence. No DDR double buffer or command-loop change is required. Check every tail/mode, fixed read3 alignment, error cancellation and response/write-drain behavior.

Candidate2: overlap load, dot and accumulation. Provide bounded input staging, correctly backpressured dot pipelines, internal output/K tags and several independent four-output accumulator contexts. Preserve sequential K-order within each output, but interleave different output groups to hide feedback latency. Removing busy alone is unsafe: current dot intermediate stages do not propagate downstream stalls to producers. Schedule outstanding arithmetic, faults, reset and final drain explicitly. Start with a2GMAC/s W4 module target (about10x current), then measure attainable cycles and routed timing. The direct single128bit WGT port supplies32W4 values/accepted cycle, giving6.4GMAC/s at200MHz for a one-row stream without added local weight replay. The64 multiplier units have12.8Gproducts/s capacity, but reaching that requires more operand bandwidth/replay architecture. Neither figure is an achieved rate. A larger compute array is not necessary for this first overlap experiment.

Candidate3: scalar engines. Cache128bit words and stream independent elements in RoPE and Vector; overlap their arithmetic with future operand reads. Replace serial15-add reduction with the same adjacent tree topology for RMS/Softmax, preserving block accumulation order. Use bounded element contexts in nonlinear arithmetic if needed, with exact operation ordering inside each element. A Softmax internal FP32 exp cache for one1024-element row requires4096bytes; save pass2 exp outputs and replay them instead of recomputing exp in pass3. Stored values must be bit-identical and retain masks/tails/reset behavior. Under fixed read3 and one-element scheduling, removing repeated score/scale/subtract/exp processing reduces the full1024-row estimate from168364 to approximately102000cycles (~1.65x); this is an analytical candidate, not measured. Parallel lanes and extra tree operators increase LUT/register/DSP and routing demands, so size them from synthesis evidence.

Candidate4, only after measuring the above: DDR tile overlap or wider/multiple WGT ports, larger arithmetic width, or integer W4-activation MACs. DDR double buffering changes bank allocation/ownership and residency costs; require measured sustained bandwidth and DMA behavior. Integer MACs need a new activation/scaling/accumulation numerical contract and fresh accuracy/reference/golden validation; W4 weight storage alone does not authorize that change. No FENCE/LOOP/JUMP/command double buffer is implied by internal executor overlap.

At2GMAC/s, dense493961216MAC/token alone would take0.247s/token. This is a component-only target and cannot be called4token/s end-to-end. Weight+FP32 group-scale bytes alone are approximately262MB/token for batch1/full logits; the64bit200MHz DMA interface ceiling1.6GB/s implies about0.164s of transfer even before other traffic, if full bandwidth were achievable. Current DMA/bank/controller overhead reduces sustained bandwidth, and exclusive-owner scheduling does not automatically overlap it with compute. SD model load is a one-time preparation cost and must be reported separately.
