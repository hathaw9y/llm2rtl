# Attention tensor control implementation

The design-local control child and actual-XPM bank topology pass `control_final005`; this is explicitly control-only evidence with mock executor memory/response transactions. The actual `attention_tensor_isa_top` instantiates the real executor, but this report does not accept its arithmetic or full integration. Shared infrastructure, old revisions, source programs and frozen packets were not changed.

`attention_tensor_pkg` fixes the canonical packed256 descriptor ABI. `generate_tensor_config.py --descriptor PATH --output-dir PATH` validates the bounded canonical19bank table against the existing program compiler and emits immutable descriptors, context, query ROM, legal compute shape tuples and physical bank depths. The active default configuration is prefill. Physical depths are powers of two, minimum64 words; request range protection uses each descriptor's smaller actual capacity, including scales and padding. New profile compilation requires regenerating and independently validating the configuration.

The controller reads a separate PS-preloaded128bit command BRAM, checks full8bit operand IDs/full32bit descriptor IDs before narrowing to5bits, then checks immutable metadata, operation shape relationships and source initialization. DMA addresses have upper32/alignment guards,23bit nonzero BTT bounds and33bit address-plus-capacity validation; exclusive end exactly2^32 is legal. Each engine handshake atomically acquires its saved exclusive owner map. Request valid and all payload fields remain stable under stall, including an unclean fault arriving during that stall. The child may use memory only from the following clock edge.

A single command is pending/issued at a time. A matching, quiescent engine completion is buffered by the RELEASE state, releases exactly the saved roles and commits the destination only after all accepted releases. A clean error may follow physical partial writes; it releases and leaves destination invalid. Wrong identity, unsolicited/duplicate completion, an unclean DMA fault, or a bank protocol fault stops progress and retains ownership until coordinated reset. Completion guarantees all memory responses were processed and final writes accepted, so there is no separate bank read-pending sideband. DMA status uses the complete5bit bank independently of the vendor tag; exactly-once transport is still required across reuse with identical bank identity.

`bank_valid[18:0]` is runtime payload validity, separate from descriptor presence. Reset cancels work, clears ownership and invalidates every bank. A new start after normal DONE preserves initialized banks, allowing a subsequent export program. Error recovery requires reset. END is accepted only after global drain; bounded missingEND never wraps PC.

The wrapper explicitly maps bank indices between descending public arrays and the unchanged ascending legacy ownership/router ABI. It maps legacy hidden GEMM role ports onto SRC0/SRC1/DST roles, enforces native128bit word/16byte-strb requests, blocks illegal capacity/owner accesses and gates physical request valid on reset. Read valid/bank pipelines remain intact, with real XPM READ_LATENCY3. Wrapper errors are sticky.

Self-verification uses34 scenarios at command BRAM latencies1 and2, including command stalls, both DMA directions, highbank18 and wrongbank16 identity, SRC0/SRC1/DST physical payload routing, atomic acquire/release monitoring, illegal opcode/reserved/range/alias/metadata/uninitialized operands, END/missingEND, partial-write clean error, wrong ID, duplicate completion, fault during command stall, zero-cycle clean completion, logical-capacity/unauthorized accesses, DDR wrap and exact-end boundary, plus reset before a live physical write. Each run recorded35 accepted acquisitions and23 accepted releases; unmatched fault reservations are intentionally removed only by reset.

Strict Verilator-Wall lint is clean except the checked-in exact-file LITENDIAN waiver for the frozen shared ascending-array ABI and its explicit wrapper adapter. No width/latch/multiple-driver/general-fatal waiver is used. The actual control-only XPM topology synthesized at5ns with WNS0.070ns, WHS0.073ns, WPWS1.958ns and zero setup/hold/pulse failing endpoints. It uses8895LUT,3119FF,38RAMB36, noDSP/URAM; DRC/methodology reports have zero checks. These are unplaced OOC estimates with external boundary hold paths explicitly excluded, not routed/board timing.

`control_try001` exposed a testbench latency-counting expectation error, corrected to count acceptance as the first of the primitive's three registered read edges. `control_try002` is preliminary. `control_final001` has no PASS result because source changed during its run. `control_final002` is superseded: independent review reproduced a latefault release/commit race. The old-source traces in `control_late_fault_repro001/002` preserve unauthorized traffic on a completion edge and range failure on a release edge causing busy=0/valid=1. `control_final003` passed the functional regression but failed5ns timing; `control_final004` retained an obsolete release-intent monitor. Only `control_final005` is the current complete source-bound control self-verification, subject to independent review.

The P1 correction exposes current raw request range/owner faults immediately and combines shared registered errors with sticky history. Every fault suppresses complete accepted ownership masks and physical forwarding. Release valid now expresses intent; its acceptance is the authoritative physical release. The controller evaluates faults before acknowledgment branches and never commits on that edge. Parallel static bank decode/fullwidth address comparisons replace the variable capacity mux; no bank fault is delayed and no5ns clock constraint is relaxed. All four completion/release-edge versus unauthorized/range combinations plus a delayed shared registered-status fault retain owner and invalid destination, with no accepted release or physical request. The measured0.070ns unplaced setup margin is small; full actualtop timing remains a separate required check.
