# 모델·보드만 지정하는 가속기 초기 생성 실험

## 목적과 범위

2026-10-06 사용자는 기존 통합 비교와 별도로, 연산기 RTL부터 새로 생성하는 실험을 요청했다. 실행당 예산은 8시간으로 선택했다. 기존 성공한 SmolLM2 구현을 제공하지 않고 전체 가속기를 생성하도록 한다.

참가자에게 전달하는 설계 요청은 다음과 같다.

> HuggingFaceTB/SmolLM2-135M 모델의 FPGA 가속기를 설계하고 구현하라. 대상 보드는 ZCU104다.

모델 checkpoint는 재현성을 위해 `93efa2f097d58c2a74874c7e644dbc9b0cee75a2`로 고정한다. 양쪽에 같은 checkpoint와 Python·Vivado/Vitis 2025.2를 제공한다. 시작 프로그램, 연산기, 모델 제어 RTL은 없다. 공통 평가·제출 규칙은 양쪽에 동일하게 제공한다. 이 규칙은 제품 정밀도나 배열 크기를 지정하지 않는다.

## 비교 조건

| 조건 | 제공 자료 | 참가자가 생성하는 것 |
|---|---|---|
| 일반 Agent | 모델·보드 요청, 실행 환경, 동일한 평가·제출 규칙 | 모델 분석부터 연산기, 메모리, 제어, host 프로그램, 검증, 빌드 전체 |
| LLM2RTL 절차 | 위 자료 + 현행 README/workflow/lowering 문서와 공통 계약 | 위와 동일 |

두 조건 모두 custom RTL을 새로 작성한다. LLM2RTL 조건에도 기존 executor, dispatcher, DataMover RTL, 통합 top, 과거 testbench, 기존 ISA interpreter, 모델별 수치/ISA/bank 설정은 제공하지 않는다. Vendor IP와 도구의 표준 보드 자료는 양쪽 모두 사용할 수 있다.

이 조건은 **완성된 프레임워크 코드 재사용** 효과가 아니라 **문서·계약에 따른 설계 절차**의 효과를 평가한다. ISA 단독 효과나 단독 연산기를 제공하는 기존 실험과 구분한다.

Agent는 정밀도·양자화, accumulator, 클럭, 배열/병렬도, memory layout, ISA/FSM, PS 실행 환경, 지원 context와 처리 token 수를 스스로 선택한다. 선택의 근거와 지원 범위를 `DESIGN_SPEC.md`에 기록한다. 기존 BF16·16×16·256-bit bank·100 MHz 선택을 정답으로 제공하지 않는다.

현행 프레임워크 문서에는 사용자와 설계를 논의하는 단계가 있다. 이번 실험에서는 사용자가 설계 선택을 Agent에 위임했다. 참가자는 스스로 근거를 기록하고 결정한다. 후속 승인 요청이나 설계 힌트를 제공하지 않는다. 실물 보드 조작은 사용자가 수행하는 별도 종점이다.

## 평가와 결과 해석

최종 목표는 전체 모델의 prefill 및 persistent KV를 사용하는 연속 decode를 PL로 실행하는 것이다. PS 또는 호스트가 모델 tensor 연산을 대신 수행하면 목표를 만족하지 않는다. 오프라인 packing·양자화·reference 계산, 전송·명령 생성·tokenization·token 선택은 허용한다.

예비 실험에서는 다음 종점을 각각 기록한다. 높은 단계의 성공을 낮은 단계의 자기 보고로 대신하지 않는다.

1. 모델 코드와 지원 경로 분석, 모델/수치/메모리/제어 명세 작성.
2. 생성된 RTL의 compile/elaboration.
3. 개별 연산기의 수치·상태·오류 시험.
4. 실제 연산기가 연결된 prefill 및 연속 decode 통합 시험.
5. 전체 top의 fully linked 합성, 자원 적합성, 선언한 clock에서 timing 검사.
6. Routed implementation과 일치하는 BIT/HWH/XSA 및 실행 패키지.
7. 사용자 수행 FPGA 시험 및 전체 출력 비교.

완성률, 최초 실제 통합 시험 결과, 수정 반복, 사용자 개입, wall time, tool 호출, token 사용량을 기록한다. 모델 연산 누락, PS 우회, 연산/주소/순서/KV/완료 오류를 구분한다. 자원과 cycle도 기록한다. 정밀도와 실행 범위가 서로 다르면 그 차이를 함께 보고한다.

첫 예비 실행은 두 조건 각 1회다. 완료한 뒤 실패·미완성도 포함하여 평가한다. 본 실험의 반복 수·수치 기준·독립 test interface는 예비 보정 후 고정한다. 예비 실행 중 제출 규칙과 목표를 바꿔 특정 참가자에게 유리하게 하지 않는다.

**현재 예비 실행의 source 검토와 독립 수치 평가가 준비되지 않은 항목은 `NOT_EVALUATED`로 남긴다.** 참가자의 `PASS` 문장만으로 독립 검증 완료율을 계산하지 않는다. 기존 보드 PASS와 새 bitstream의 검증 결과는 분리한다.

## 실행 관리

같은 Agent 모델 `gpt-6.1-sol`, reasoning `medium`, 실행당 wall budget 28,800초를 사용한다. Token 사용량은 종료 이벤트로 기록하며 이번 예비 실험에는 token 상한을 적용하지 않는다. 공유 도구 자원 영향을 줄이기 위해 순차 실행한다. 조건 순서는 고정 seed로 결정하고 launch 전에 기록한다.

빈 작업 디렉터리와 새 대화를 사용한다. OS mount/PID 격리로 기존 저장소, 다른 실행, hidden 평가 자료, 과거 대화와 skills를 숨긴다. 인증 파일은 읽기 전용으로 연결하며 복사하거나 출력하지 않는다. 공개 인터넷에서 기존 가속기 구현을 가져오는 것은 금지하고 도구 로그로 감사한다. API 인증을 위한 network를 유지하므로 외부 정보 차단 전체를 OS로 증명했다고 주장하지 않는다.

감독기는 실행 중 후보를 수정하거나 기술 힌트를 보내지 않는다. 참가자가 조기에 종료하면 실제 종료 시간과 남은 실패를 기록한다. 8시간을 채우도록 후속 지시를 보내지 않는다. Timeout은 원본 로그와 소스를 보존하고 실패/미완성으로 기록한다.

예비 실행 종료는 전체 가속기 완료와 다르다. `status.json`과 외부 저장소의 supervisor/participant 상태 파일에 실제 실행 상태를 기록한다.

## 구현 언어 정정 (2026-10-06)

사용자 요구에 따라 모든 모델 연산기·제어·연결을 synthesizable Verilog/SystemVerilog로 직접 작성한다. HLS, C/C++ 합성 또는 고수준 프로그램으로 모델 RTL을 생성하는 방식은 허용하지 않는다. C/C++·Python은 host 프로그램·packing·reference·test driver에 사용할 수 있다. Vendor infrastructure IP와 leaf primitive는 허용하며 실제 tensor 검증은 RTL datapath를 실행해야 한다.

초기 문구에 이 제한이 없어서 HLS를 선택한 이전 시도는 `cold_start_v1_hls_scope_attempt002`에 보존하고 이번 직접 RTL 비교에서 제외한다. 양쪽 모두 새 대화와 빈 작업 공간에서 8시간 예산으로 다시 시작한다. 기존 HLS 결과를 Verilog 생성 실험의 성공 또는 실패로 집계하지 않는다.
